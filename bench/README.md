# Benchmarks

mobilepkg is measured the way a user runs it, one process per call from start to exit, with [himorime](https://github.com/nao1215/himorime). himorime builds mobilepkg, runs each command in interleaved rounds, and reports latency, CPU time, peak RSS and, for the large inputs, throughput.

```console
$ go install github.com/nao1215/himorime@latest
$ make bench            # himorime run bench
$ make bench-compare    # himorime compare --against main bench
```

## Regression suite: himorime.yaml

`make bench-compare` checks main out into a temporary Git worktree, builds it and your working tree, and measures both in the same rounds, so a background job slows both revisions instead of one. `BASE=v0.5.2 make bench-compare` compares against another revision. `himorime run --filter 'inspect 100k' bench` measures one benchmark.

On a pull request, `.github/workflows/bench.yml` runs `himorime ci bench` the same way, with the base of the pull request as the base, on one runner. The job fails when a command is slower, uses more CPU time or more memory than the base beyond the tolerance in `himorime.yaml` with 95% confidence. A difference too close to call is reported as inconclusive and does not fail the job. The comparison is on the job summary page and the JSON report is kept as an artifact.

The packages are generated by `gen.sh` before measuring and nothing is downloaded. `gen.sh` runs the Go program in `genapk/`, which copies every entry of the committed `testdata/android/androgoat_rich.apk` (binary manifest, v1 signature, resources) and adds a `classes.dex` of N strings, one in a hundred a cleartext URL. The count of DEX strings is the size in the benchmark names. Both revisions run the working tree's `gen.sh`, so they read the same bytes.

| Benchmark | Commands | Measures |
|-----------|----------|----------|
| `version` | `mobilepkg version` | starting mobilepkg |
| `inspect 10` | `mobilepkg inspect` as JSON, as Markdown, with `--fail-on warn` | an APK with a DEX of 10 strings, where start-up, the manifest, the signature and the resources dominate |
| `inspect 100k` | `mobilepkg inspect` as JSON, as Markdown, with `--fail-on warn` | the DEX scanners over 100 000 strings, the findings, and each output |
| `compare 10` | `mobilepkg compare old.apk new.apk` | inspecting two small APKs and comparing them |
| `compare 100k` | `mobilepkg compare old.apk new.apk` | inspecting two APKs with a DEX of 100 000 strings each and comparing them |
| `inspect error` | `mobilepkg inspect` on a file that is not a package | the error path, exit 1 |

`--fail-on warn` exits 1 on the findings of the AndroGoat fixture; the suite expects that status.

Not measured: IPA, XAPK, APKS and AAB packages. The repository commits no fixture of those formats to build them from; XAPK, APKS and AAB reach the same manifest, signing and DEX code as an APK once the archive is opened, and IPA inspection reads plists and signatures only.

Numbers from different machines are not comparable; compare revisions on one machine, as `make bench-compare` and CI do.
